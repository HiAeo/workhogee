# M2.3 薄 Worker 架构：API 契约 + 压测报告

## 一、架构变更（M2.2 → M2.3）

M2.2 是同步大 base64 pipeline：浏览器把 1-3MB 商品图 base64 POST 到 Worker，Worker 在内存里串行调视觉/PicWish/Seedream，把 50-100MB base64 在内存里往返，128MB isolate 连续 3 次就 OOM 崩溃（502），成功率 44%。

M2.3 改为「TOS 中转 + 异步 job + 单步调用」：

- 浏览器直传 TOS（预签名 PUT），原图字节不过 Worker；
- `POST /pipeline` 只收 `{ key }`，立刻返回 `jobId`；
- 前端轮询 `GET /job?id=`，每次请求在 Worker 内同步跑**一个 step** 再返回；
- Seedream 用 `response_format=url`，视觉模型用公网 URL 输入；
- PicWish 返回的 base64 PNG 立即转存 TOS 后释放，Worker 全程不持有大图像素。

> 关键落地决策：Cloudflare 免费版 Worker 在响应返回后无法维持长 `waitUntil` 后台任务（实测 ~25s 后被冻结）。因此 job 不跑后台，而是**由前端轮询驱动单步推进**——每次 GET /job 执行一个 step（identify/cutout/scene/marketing/copy/qc），跑完写 KV 再返回。这比 waitUntil 更稳，也更贴合「单步化」要求。

## 二、新 API 契约

### POST /upload-url
会员鉴权（`Authorization: Bearer <token>`）。
请求：`{ "contentType": "image/jpeg" }`
响应 200：
```json
{ "ok": true, "uploadUrl": "https://workhogee-assets.tos-cn-beijing.volces.com/uploads/{memberId}/{ts}_{rand}.jpg?X-Tos-...",
  "key": "uploads/{memberId}/{ts}_{rand}.jpg", "expiresSec": 600, "contentType": "image/jpeg" }
```
前端拿到 `uploadUrl` 后**直接 PUT 二进制**到该 URL（Content-Type: image/jpeg），200 即上传完成。

### POST /pipeline（异步新版）
会员鉴权。
请求：`{ "key": "TOS object key", "category"?: "家居百货", "style"?: "ins风" }`
- 不再接收 base64 `image`。
- 服务端依次做：key 归属校验 → HEAD TOS → 并发槽位（每用户 2）→ 额度扣减 → 创建 job。
响应 202：`{ "ok": true, "jobId": "job_xxx", "status": "running" }`
错误：
- 400 `forbidden_key` / `object_not_found`
- 402 `quota_exhausted`
- 429 `queue_full`（排队中，每用户最多 2 个并行）

> 兼容：旧请求体带 `image`（base64）仍走 M2.2 同步逻辑（已标记 deprecated），前端新流程请用 key 模式。

### GET /job?id=<jobId>
会员鉴权（且 job.memberId 必须等于当前会员）。
响应 200：
```json
{
  "ok": true, "jobId": "...", "status": "running|done|error", "progress": 0-100,
  "steps": [ {"name":"identify","status":"done","ms":6351}, ... ],
  "results": {
    "category": {"name":"...","source":"vision|user"},
    "productAttributes": {"productName":"...","material":"...","color":"...","sellingPoints":[...],"packagingText":"..."},
    "cutoutKey": "cutouts/{member}/xxx.png",
    "cutoutUrl": "https://...tos.../cutouts/...png?X-Tos-...",   // 每次轮询刷新 1h 预签名
    "cutoutWidth": 1000, "cutoutHeight": 1000,
    "sceneUrls": ["https://ark-content-generation...", "...", "..."],  // Seedream 直链（24h 有效）
    "marketingUrl": "https://ark-content-generation...",
    "compositeGuide": {"scene":[...],"marketing":{...}},
    "copy": {"title":"...","sellingPoints":[...],"description":"...","channels":{"taobao":"...","xhs":"...","amazon":"..."}},
    "qualityCheck": {"passed":true,"available":true,"scores":{"consistency":1,"textReadability":1,"edgeCleanliness":0.95},"issues":[]}
  },
  "errors": [], "quota": {"remaining":...}, "createdAt": 1790...
}
```
前端每 3-5s 轮询一次；前端可直接用 `cutoutUrl`（TOS 预签名）和 `sceneUrls`/`marketingUrl`（Ark 直链）做 Canvas 合成，无需后端中转像素。

### Step 顺序
identify（视觉识别）→ cutout（PicWish URL→PNG→TOS）→ scene（3 张空背景，url 输出）→ marketing（营销背景）→ copy（文案）→ qc（单图 URL 质检，15s 超时）。

## 三、压测数据

环境：线上 https://api.workhogee.com ，测试图 m21-test/02_3c.jpg（333KB），单一会员账号。

### 连续 5 次串行
| # | 总耗时 | 结果 |
|---|---|---|
| 1 | 99.0s | done |
| 2 | 87.7s | done |
| 3 | 122.3s | done |
| 4 | 95.6s | done |
| 5 | 159.6s | done |

### 2 次并行（同一会员，触发并发锁上限=2）
| 任务 | 总耗时 | 结果 |
|---|---|---|
| A | 104.6s | done |
| B | 96.7s | done |

### 汇总
- 成功率：**7/7 = 100%**（M2.2：4/9 = 44%）
- 连续成功上限：**7 次无失败**（M2.2：3 次后必崩）
- 502：**0 次**（M2.2：连续跑即 502）
- P50 耗时：**~99s**（M2.2：~80s；略增来自轮询开销，换取零崩溃）
- 并发：2 并行同时跑通，第 3 个会收到 429 queue_full。

## 四、与 M2.2 对比

| 指标 | M2.2 同步 base64 | M2.3 TOS 中转 + 异步 job |
|---|---|---|
| 单次成功率 | 44% | 100%（7/7） |
| 连续成功上限 | 3 次 | ≥7 次无崩 |
| 502 | 频繁 | 0 |
| Worker 内存峰值 | 50-100MB base64 | <5MB（仅 PicWish 返回瞬时） |
| 原图字节路径 | 浏览器→Worker→视觉/PicWish | 浏览器→TOS→视觉/PicWish（直链） |
| Seedream 输出 | Worker 收 5MB b64 再回传浏览器 | Worker 只回传 URL（0 字节） |
| 前端等待 | 同步 80s 长连接，断了就崩 | 立即返回 jobId，轮询拿 URL |

## 五、已知限制 / 后续
- `GET /job` 每次会同步跑一个 step（最长 ~95s），前端轮询间隔建议 3-5s；并发轮询靠 `stepRunningAt` 25s 窗口防重入。
- 免费版 Worker 不跑后台 waitUntil；job 全靠轮询推进，用户关页面则 job 停在最近一步（KV 保留 2h，重新打开可续）。
- TOS 浏览器 PUT 的 CORS 已实测可用（未额外配 CORS 规则即 200）。
- Scene 步一次轮询内并行出 2 张 + 串行第 3 张，单步 ~16s；Marketing/copy/qc 各 1 次轮询。
