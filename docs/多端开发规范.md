# WorkHogee 多端开发规范（工程宪法）

> 版本：v1.0（2026-09）
> 适用：Web（当前）、PWA、微信小程序（未来），以及同一套 Cloudflare Worker 后端。
> 强制力：**本规范对所有新代码强制生效；存量代码按"迁移路线"渐进收敛。** 任何 PR 与本规范冲突时，以本规范为准；确需偏离，须在 PR 描述里写明原因与回收计划。

一句话：

> **现在写 Web 的时候，心里要想着它以后还要跑在 PWA 和微信小程序上。业务逻辑要独立，API 要通用，UI 要可替换。**

---

## 0. 三条铁律

1. **业务逻辑与 UI 分离**：图片处理、文案生成、任务状态、数据计算、计费判断等，必须落在 `services/` 或 `utils/`；页面 / 组件只负责展示与交互，且**只通过 services 调后端**，不直接 `fetch`。
2. **平台能力走适配层**：`window` / `document` / `localStorage` / `<input type="file">` / 浏览器路由 / Web Speech / Notification 等，**只允许出现在 `adapters/web/`**。可移植代码里出现这些即视为违规。
3. **接口端中立**：所有端共用一套后端 API，Bearer Token 鉴权、统一 JSON 包络，不为 Web 定制参数或返回。详见 [`API契约.md`](./API契约.md)。

---

## 1. 目标分层与依赖方向

```
┌─────────────────────────────────────────────────────────┐
│  UI 层（可替换）                                          │
│  web/src/ui/*        【Web 专用】  DOM 页面 / Web Components │
│  miniapp/src/ui/*    【小程序专用】Taro/React 页面与组件      │
└───────────────┬─────────────────────────────────────────┘
                │ 只调用，不反向依赖
┌───────────────▼─────────────────────────────────────────┐
│  services/ 业务编排（可复用，框架无关，纯 JS/TS）            │
│  generate / copy / storyboard / tasks / works / kb /      │
│  publish / analytics / auth / billing / feed ...          │
└───────┬───────────────────────────────┬───────────────────┘
        │ 调用                           │ 调用
┌───────▼──────────────┐      ┌──────────▼───────────────────┐
│ adapters/ 平台适配层  │      │ utils/ 纯函数（可复用）         │
│ http storage upload  │      │ 校验/格式化/压缩/提示词/计费/枚举│
│ router auth notify   │      └──────────────────────────────┘
│ device media         │
└───────┬──────────────┘
        │ 经 httpClient（端中立）
┌───────▼──────────────────────────────────────────────────┐
│  后端（唯一事实源）Cloudflare Worker  /api/...              │
└──────────────────────────────────────────────────────────┘
```

**依赖方向只能从上到下，禁止反向、禁止跨层**：

- `ui` 可依赖 `services / utils / adapters 的接口`；
- `services` 只依赖 `utils` 与 **adapters 的抽象接口**（通过依赖注入 / 统一 import 入口），**不得 import 任何 `adapters/web` 具体实现，不得碰 DOM**；
- `utils` 不依赖任何层，是纯函数（同输入必同输出，无副作用、无 IO）；
- `adapters/web` 可以碰浏览器 API，但**不含业务规则**。

> 迁移到 Taro 时：`services / utils` 原样复用；新增 `adapters/miniapp`（实现同一套接口，内部用 `Taro.*`）；`ui` 用 React 重写。这就是"一次开发，多端复用"的落点。

## 2. 技术选型与"何时切框架"

| 项 | 决策 |
|---|---|
| 现阶段 Web | **维持原生 HTML/CSS/JS，不引入打包构建、不推倒重写**（线上稳定优先） |
| 新代码纪律 | 即使仍在单文件阶段，新增可移植逻辑也写成**无 DOM 的 ES Module / 纯函数**，平台差异走 adapters |
| 未来跨端框架 | **Taro 4 + React + TypeScript**（一套代码出微信小程序 + H5；H5 再叠加 PWA） |
| 不选 uni-app 的原因 | uni-app 对 Vue 更友好；本项目明确要复用 **React** 组件与生态，Taro 的 React/TS、H5+微信小程序成熟度更匹配 |
| 状态 | 框架无关的 service 单例 + 订阅（发布订阅 / 轻量 store）；进入 React 后可平滑接 Zustand |
| 后端 | Cloudflare Worker + KV + TOS + 火山方舟，已上线，**多端共用，不另起后端** |
| Next.js / SSR | **暂不采用**；若未来引入，业务页按 CSR/SPA 写，避免依赖 `getServerSideProps` 等 SSR 专有 API（小程序用不到） |

**正式从 vanilla 切到 Taro 工程的触发条件（满足其一即启动，由负责人拍板）：**

1. 拿到微信小程序 **AppID 与企业主体认证**，小程序正式立项；或
2. 明确要做第二个端（PWA 独立分发 / 桌面壳）且 UI 复杂度继续上升；或
3. `workbench.html` 内联业务逻辑已通过迁移路线 M1–M3 抽离出 ≥ 60%，切换只剩 UI 重写。

在条件满足前，**不做一次性大重写**，只做"新代码守纪律 + 存量随功能迭代抽离"。

## 3. 平台适配层（adapters）契约

适配层按能力拆分；每个能力先定义**端中立接口**，再分别给 Web / 小程序实现。services 只认接口。

### 3.1 httpClient（网络）

```ts
// 统一出口；内部处理 BaseURL、Token 注入、JSON 包络解包、错误码、超时、重试
interface HttpClient {
  request<T>(req: {
    method?: 'GET' | 'POST' | 'PUT' | 'DELETE';
    path: string;            // 一律相对路径，如 '/api/tasks'，不写死域名
    data?: unknown;          // 对象自动 JSON；文件走 uploader，不走这里
    headers?: Record<string, string>;
    timeoutMs?: number;
    signal?: { aborted: boolean }; // 端中立的取消信号（Web 映射 AbortController）
    retry?: { times: number; onCodes: string[] };
  }): Promise<T>;            // 成功返回 data；失败抛 ApiError{code,message,httpStatus}
}
```

- Web：`fetch`；小程序：`Taro.request`；PWA：同 Web（可叠加后台同步）。
- **Token 由 httpClient 自动注入** `Authorization: Bearer <token>`，业务代码不手动拼。
- 禁止在 services/ui 里直接 `fetch(` / `XMLHttpRequest`。

### 3.2 storage（本地存储）

```ts
interface StorageAdapter {
  get<T>(key: string): Promise<T | null>;
  set(key: string, value: unknown): Promise<void>;
  remove(key: string): Promise<void>;
  clearNamespace(ns: string): Promise<void>;
}
```

- Web：小数据 `localStorage`，大数据 / 图片缓存走 **IndexedDB**（统一封装，不直接调）；小程序：`Taro.getStorage / setStorage`（单 key 上限 1MB，总量 10MB，超限走 TOS）。
- **统一加命名空间前缀 `hogee:`**，并集中在一个 `keys.ts` 常量里声明，禁止散落字符串。现有键迁移对照见附录 A。
- 存储不可用（隐私模式 / 配额满）要静默降级，不得让业务崩溃。

### 3.3 uploader（选图 / 压缩 / 上传）

```ts
interface UploadAdapter {
  // 选图 / 拍照 / 选视频；不与 <input type="file"> 绑定
  pickMedia(opts: { count?: number; mediaType: ('image'|'video')[]; source?: ('album'|'camera')[] }):
    Promise<PickedFile[]>;                                        // {uri,name,size,type,width,height}
  compressImage(uri: string, opts: { maxEdge?: number; quality?: number; mime?: 'jpeg'|'png'|'webp' }):
    Promise<PickedFile>;
  convertFormat?(...): Promise<PickedFile>;                       // 格式转换（能力不足时回退服务端）
  // 先向 /api/storage 取预签名 URL，再直传 TOS；返回稳定资源引用（key/url）
  uploadToStore(file: PickedFile, onProgress?: (pct:number)=>void): Promise<AssetRef>;
}
```

- Web：选图用隐藏 input / 拖拽，**但封装在 adapter 内**；压缩用 Canvas（见 3.8）。小程序：`Taro.chooseMedia / compressImage / uploadFile`。
- **多图、压缩、格式转换**：端上做轻压缩省流量，重 / 不支持的转换交后端；接口对两端一致。
- 业务接口（如 `/generate`）v2 起只传 **AssetRef 引用**，不再传超大 base64（见 API 契约）。
- 预览 / 裁剪做成独立组件 `<MediaCropper>`，数据进出走 `PickedFile`，不直接读 input DOM。

### 3.4 router（路由 / 导航）

```ts
interface RouterAdapter {
  navigate(to: RouteName, params?: Record<string, unknown>): void; // 入栈
  replace(to: RouteName, params?: Record<string, unknown>): void;
  back(delta?: number): void;
  current(): { name: RouteName; params: Record<string, unknown> };
  onChange(cb: (r)=>void): () => void;
}
```

- **集中维护一张路由表**（`routes.ts`：home / workbench / works / knowledge / publish / analytics / connections / account / login …）。
- Web：hash 或 history 由 adapter 内部决定（推荐 hash，免服务端 rewrite）；**禁止业务代码直接 `history.pushState` / `location.href=`**。
- 小程序：映射为页面栈 `Taro.navigateTo / redirectTo / navigateBack`，`RouteName` 与小程序 `app.config.ts` 页面一一对应。
- 工作台内部"阶段 / 视图切换"属于**组件状态**，不是路由，不占页面栈。

### 3.5 auth（登录 / 用户体系）

```ts
interface AuthAdapter {
  login(provider: 'wechat'|'phone'|'email'|'feishu'|'dingtalk'|'qq', payload?: LoginPayload): Promise<Session>;
  logout(): Promise<void>;
  getSession(): Session | null;
  getToken(): string | null;
  refreshToken?(): Promise<Session>;
  onChange(cb: (s: Session|null)=>void): () => void;
}
```

- 用户体系与授权方式解耦：services 只调 `auth.login(provider)`，**新增一种登录只加一个 provider 适配器，业务逻辑零改动**。
- 小程序：`wx.login` 拿 code → 服务端换 session；Web：微信扫码 / 手机验证码 / 邮箱 / 飞书 / 钉钉 / QQ（启用项由配置下发，不在端上写死）。
- Token 存 storage（经 3.2），httpClient 自动携带；敏感操作走短期 access + 刷新。
- 验证码内测期可回传 devCode（无 SMS / 邮件网关），但要由 `GET /config` 开关控制，正式通道接入后关闭。

### 3.6 notify（通知 / 消息）

```ts
interface NotifyAdapter {
  requestPermission(scope?: string): Promise<'granted'|'denied'|'default'>;
  subscribe(channel: string, opts?: unknown): Promise<SubscriptionRef>; // Web: PushManager+VAPID；小程序: requestSubscribeMessage
  onMessage(cb: (m: PushMessage)=>void): () => void;
  localNotice(title: string, body?: string, data?: unknown): void;       // 前台本地提示
}
```

- Web/PWA：Web Push（VAPID + Service Worker `push` 事件）；小程序：订阅消息（模板需 AppID）。
- **业务里只发"有一条任务完成 / 发布结果"的领域事件**，由 notify service 决定走哪个通道；禁止把推送逻辑写死在页面里。

### 3.7 device（设备 / 系统能力）

```ts
interface DeviceAdapter {
  getSystemInfo(): { platform:'ios'|'android'|'windows'|'mac'|'web'; pixelRatio:number; screenW:number; screenH:number; safeArea?: EdgeInsets };
  clipboard: { set(text:string):Promise<void>; get():Promise<string> };
  vibrate?(ms?:number): void;
  saveImageToAlbum(uri:string): Promise<void>;     // Web: 触发下载；小程序: 保存相册
  share?(payload: SharePayload): Promise<void>;    // 小程序 onShareAppMessage；Web 用 Web Share / 复制链接兜底
  speech?: { recognize(opts): SpeechHandle };     // 语音输入：Web Speech；小程序插件/录音转写，接口对齐
}
```

### 3.8 media（Canvas / 图片像素处理）

- 把"读文件为位图、缩放、加水印、导出 blob、首帧抽帧"等收敛到 `adapters/*/media`。
- Web 用 Canvas / OffscreenCanvas；小程序用 Canvas 2D。对外暴露同一组纯逻辑入口（`utils/image` 算尺寸 / 版式，adapter 只做像素执行）。
- 合规打码（车牌 / 人脸 / VIN）属**服务端能力**，端侧不承诺，见 `capabilities` 开关。

## 4. services 与 utils（业务核心，多端复用）

- `services/*`：一个业务域一个模块，**只做编排与状态**，IO 全走 adapters。本项目至少包含：

  | service | 职责 | 对应后端 |
  |---|---|---|
  | `authService` | 会话 / 登录态 / 账号资料 | `/api/member/*` |
  | `generateService` | 出图、多图、尺寸 / 清晰度 / 格式 | `/generate` `/qc` `/verify` |
  | `copyService` | 文案 / 卖点生成 | `/copy` |
  | `visionService` | 识图、商品 / 行业识别 | `/identify` |
  | `videoService` | 分镜 / 视频（内测为分镜+前端合成 fallback） | `/storyboard` |
  | `taskService` | 任务列表、状态、置顶 / 重命名、跨端同步 | `/api/tasks` `/api/tasks/sync` |
  | `worksService` | 我的作品（图 / 视频 / 文案分类、二次创作） | `/api/storage` + 本地 |
  | `kbService` | 企业知识库（引导式分类录入、检索、预填） | `/api/member/kb` |
  | `publishService` | 半自动分发就绪包、发布登记、最后一下用户自点 | `/api/member/publish` |
  | `analyticsService` | 展现 / 浏览 / 留资等效果数据 | `/api/analytics` |
  | `feedService` | Hogee 创作探索（官方素材墙、做同款） | `/api/feed` |
  | `billingService` | 套餐 / 加量包 / 额度 | `/api/member/billing` |

- `utils/*`：**纯函数**，无 IO、无随机时间依赖（时间 / 随机由参数注入，便于测试）。如：提示词拼装、尺寸换算、文件校验、枚举与行业映射、计费计算、文案模板、数据格式化、防抖节流。
- 现状：以上逻辑当前内联在 `workbench.html`（约 5000 行）。迁移时**按 service 成块搬出，行为保持不变**，每搬一块跑回归（见第 11 节）。

## 5. 浏览器 API 收敛清单（什么能用、在哪用）

| API / 对象 | 允许出现的位置 | 说明 |
|---|---|---|
| `fetch` / `XMLHttpRequest` | 仅 `adapters/web/httpClient` | 统一包络、Token、错误 |
| `localStorage` / `sessionStorage` / `IndexedDB` | 仅 `adapters/web/storage` | 键名走 `keys.ts` 常量 |
| `document` / DOM 增删改查 | 仅 `ui/` | services/utils 禁止 |
| `window`（尺寸 / 事件 / open） | `adapters/web` 或 `ui/` | 业务逻辑不读 window |
| `<input type="file">` / 拖拽文件 | 仅 `adapters/web/uploader` 内部 | 组件只调 `pickMedia` |
| `history` / `location` 跳转 | 仅 `adapters/web/router` | 页面内用 router 表 |
| `Notification` / Service Worker / Push | 仅 `adapters/web/notify` | |
| Web Speech（语音输入） | 仅 `adapters/web/device.speech` | |
| `URL.createObjectURL` / `FileReader` / Canvas | 仅 `adapters/web/media`、`uploader` | |
| `alert/confirm/prompt` | **禁止**（用统一弹层组件） | 现状的 `prompt/confirm` 需替换 |
| `setTimeout/interval`、随机、Date | utils 中允许但**由参数注入**以便测试 | 业务时间取服务端或单一 clock |

> 进入 Taro 工程后，用 ESLint `no-restricted-globals` + 目录边界（`services|utils` 禁止 import DOM/平台 API）在 CI 卡死，违规不能合并。

## 6. 样式与布局跨端

- **设计 token 集中管理**：颜色（深色极光底、品牌橙 `#FB923C`、五伙计角色色）、字号、字重、间距、圆角、阴影、动效时长 / 缓动，全部定义为 CSS 变量（Web）与一份可被 Taro 引用的 token（SCSS/JS 变量），**两端同值**。
- **布局只用 Flexbox / Grid + 相对单位**：`rem / em / vw / % / fr`，容器最大宽度 + 流式栅格。
  - 禁止用固定像素定宽高（仅 1px 发丝线、图标点阵、已知最大内容宽可豁免）。
  - 断点：手机 `<640px`、平板 `640–1024`、桌面 `>1024`；**笔记本 1366×768 / 1440×900 为优先验收视口**（一屏放不下就压缩板块高度）。
  - 小程序用 `rpx`（以 750 设计稿为基准），H5 用 rem；token 提供换算，不允许各写各的魔法数字。
- 避免复杂 CSS 选择器、深层穿透、浏览器私有属性；必要的 `-webkit-` 仅写在适配样式并双端验证。
- 动效遵守 `prefers-reduced-motion`；非用户触发动效克制。
- 图标统一**单色线性内联 SVG**（禁彩色功能图标 / emoji；例外：五伙计 IP、平台品牌色 logo、彩虹字、GLOBAL 角标）。
- 顶部导航 / 底部信息多页绝对一致，由共享布局组件承载，不逐页复制。

## 7. 上传与文件处理（专项）

1. 上传接口支持**多图、压缩、格式转换**，Web 与小程序调用**同一个** `/api/storage` 预签名 + TOS 直传流程。
2. 选图、压缩、预览、裁剪封装为独立组件 / adapter，**不与 `<input type="file">` 强绑定**。
3. 大文件走"预签名直传 + 进度回调"，业务接口只传资源引用；base64 内联仅作为 v1 小图兜底。
4. 文件类型 / 大小 / 尺寸校验放 `utils/file`（纯函数，双端共用），错误提示走统一组件。
5. 原图与成品图跨端同步：统一存 TOS 私有前缀 `u/<memberId>/`，本地只缓存，不把"本机 localStorage"当云端。

## 8. 登录与用户体系（专项）

- 用户体系独立于端：会话、会员套餐、额度、账号资料都在后端 `/api/member/*`，端上只存 token 与必要缓存。
- 授权方式可插拔：微信（小程序 `wx.login` / Web 扫码）、手机验证码、邮箱、飞书、钉钉、QQ；新增方式只加 adapter + 后端 provider，**不动业务逻辑**。
- 登录 / 注册 UI 与工作台深色风格统一；按钮真实可用，未开通的授权方式不展示或标"即将开放"，不做假按钮。
- 未登录可用能力与需登录能力由 `GET /config` + 后端 401 共同决定，端上不硬编码权益。

---

## 9. 推送与消息（专项）

- 通知是独立 service：领域事件（任务完成、发布结果、额度预警）→ notify service → 按端选 Web Push / 订阅消息。
- Web/PWA：Manifest + Service Worker（建议 Workbox 或等价手写），离线壳 + 后台同步；VAPID 公钥由后端下发。
- 小程序：订阅消息模板需 AppID 与类目，未就绪前 adapter 的 `subscribe` 返回"未开通"，UI 不承诺。
- 不在任何页面里内联推送注册 / 令牌上报代码。

## 10. 工程结构与复用（Taro / React）

目标 monorepo（切换框架时建立，现阶段只约束目录命名与模块边界）：

```
packages/
  core/          # services + utils + 类型 + 路由表 + 枚举（纯 JS/TS，无 DOM，无 Taro 依赖）
  api-types/     # 与后端 API契约.md 对齐的请求/响应类型（可由 OpenAPI 生成）
apps/
  web/           # 现阶段 vanilla（迁入）；未来 H5/PWA
  miniapp/       # Taro + React 微信小程序
  pwa/           # 可与 web 合并为同一 H5 + SW
```

- React 组件放在 `apps/miniapp`（及未来 H5），`packages/core` **不 import React / Taro / DOM**，保证可被任意端引用。
- 若用 Next.js：核心业务按 CSR 写，慎用 SSR 专有数据获取；首屏营销页可 SSR，工作台不依赖 SSR。
- 接口类型以 [`API契约.md`](./API契约.md) 为准，建议后端导出 OpenAPI，前端生成 `api-types`，避免手写漂移。

## 11. 存量迁移路线（增量、可随时停、每步可上线）

> 原则：**纯搬移 + 收敛，行为不变；每一步都跑本地 e2e / 截图回归与线上真机回归后才合并。** 改动前先备份到 `_backup/`。

- **M0 立规范（本次）**：README + 本规范 + API 契约；新代码即刻守纪律。
- **M1 网络 / 鉴权 / 存储收敛（最高优先，低风险）**
  - 新增 `web/src/adapters/web/{httpClient,storage,auth}.js` 与 `keys.ts`；
  - 把 `workbench.html` / `member-auth.js` 里的 `fetch` 收口到 httpClient（自动注入 token、统一错误）；
  - 把散落的 `localStorage` 键（附录 A）收口到 storage adapter；
  - 行为不变，回归：登录、出图、对话、刷新持久化。
- **M2 上传 / 作品 / 任务 / 知识库 service 化**
  - uploader（多图 / 压缩 / TOS 直传）、worksService、taskService、kbService 搬出；
  - 大对象改 IndexedDB；替换 `prompt/confirm` 为统一弹层。
- **M3 发布 / 通知 / 路由 / 设备**
  - publishService、notifyService、router 路由表、device（语音输入 / 保存相册 / 分享）。
- **M4 UI 组件化（vanilla Web Components 或直接并入 M5）**
  - 对话框、三下拉、交付区、素材墙、账号菜单等抽成可复用组件，样式走 token。
- **M5 Taro 工程**
  - 建 `packages/core`（搬 services/utils）、`apps/miniapp`（React 重写 UI + `adapters/miniapp`）、H5 叠加 PWA；
  - 后端零改动（接口本就端中立），按 API 契约补齐缺口。

每个 M 独立成批 PR；**不为迁移而迁移**，触碰某功能时优先把该功能所在模块顺手收敛（童子军规则）。

## 12. 注释与模块标注（强制）

每个文件**头部**必须标注可移植性与输入输出：

```js
/**
 * @file 文案生成编排
 * @portable        // 可复用：无 DOM、无平台 API，Web / 小程序共用
 * 或 @platform web // Web 专用：仅允许出现在 adapters/web 或 ui
 *
 * 输入：product(AssetRef)、industry(string)、channels(string[])
 * 输出：Promise<{ title:string; body:string; tags:string[] }>
 */
```

- `@portable`：services / utils / 类型 / 枚举 / 路由表 / 纯样式 token。
- `@platform web` / `@platform miniapp`：该端 adapter 与 UI。
- 关键 service / util 用 JSDoc（未来切 TS 即类型）写清 `@param @returns @throws`。
- 后端新接口必须先在 [`API契约.md`](./API契约.md) 登记，再实现。

## 13. 安全红线（历史踩过坑，必守）

- **任何 AI / 云服务 Key 只存在 Worker（secret / KV）**，前端、小程序、PWA、仓库、日志、报错里一律不得出现；前端不直连火山方舟。
- 历史泄露 Key 必须立即吊销并轮换（已发生过应急，见 #157）；提交前用密钥扫描，禁止把 `.dev.vars`、AccessKey、Token 写进代码 / 截图 / 文档。
- 鉴权统一 Bearer Token；httpClient 是唯一注入点；不把 token 放 URL query。
- 不索要、不存储用户自媒体平台密码 / Cookie；OAuth 走官方授权，未接通只登记。
- 日志不打印密钥、手机号全量、身份证等 PII；错误上报脱敏。
