WorkHogee 出海专版
广告平台 API 资质申请指南

版本：v1.0 日期：2026-09 适用团队：技术部 / 增长团队 / 合规组 密级：内部

1. 概述

WorkHogee 出海专版的核心能力之一是广告转化数据回传（Conversion API / Server-Side Event）。当海外客户在官网完成表单提交、下载白皮书、在线咨询等转化动作后，系统需要将这些事件实时回传给 Meta、Google、TikTok 三大广告平台，用于：

  • 优化广告投放模型（Lookalike / 自动出价）
  • 降低归因误差（相比纯浏览器 Pixel，Server-Side 回传受 iOS/隐私政策影响更小）
  • 提升广告 ROI，让平台算法"学得更快"

要实现这一能力，必须先向各广告平台申请 API 开发者资质。这是出海专版的P0 前置任务，未完成资质申请前，回传功能无法上线。

平台优先级

优先级平台原因预计周期
P0 最优先Meta (Facebook/Instagram)出海客户主投渠道，CAPI 直接决定转化回传质量2-3 周
P1 次优先Google Ads搜索+展示广告覆盖广，开发者Token申请相对快1-2 周
P2 跟进TikTok年轻市场增长快，但企业认证门槛较高2-3 周
整体时间线预估：三个平台全部完成审核 + 联调，预留 6-8 周。建议从 Meta 开始并行启动 Google，TikTok 视业务需要跟进。企业认证（Business Verification）是三个平台共同的前置卡点，务必第一时间提交。

2. Meta Business App 申请流程 P0

Meta 的 Conversions API（CAPI）是出海专版的核心回传通道。以下流程覆盖从创建 App 到通过 App Review 的完整步骤。

前置条件

  • Facebook 个人账号：需完成实名认证，建议使用公司高管/创始人账号（审核员会核对申请人身份）
  • Business Manager (BM) 账号：在 business.facebook.com 创建，需绑定企业主页
  • 企业认证（Business Verification）：在 BM → 安全中心 提交营业执照、电话验证、域名验证。这是最容易卡住的环节，建议第一时间启动
  • 企业官网：必须公网可访问，且包含隐私政策（Privacy Policy）页面
  • 广告账户：在 BM 下至少有一个活跃的广告账户（无需充值，存在即可）
1
创建 Meta App

访问 developers.facebook.com，使用管理员账号登录：

  1. 右上角 My Apps → Create App
  2. 选择应用类型：Business（商务）
  3. 填写 App 名称：WorkHogee Global；联系邮箱用公司邮箱
  4. 选择关联的 Business Account（BM）
  5. 点击 Create App，完成安全验证
2
添加 Conversions API 产品

进入 App Dashboard → Add Product：

  1. 在产品列表找到 Conversions API，点击 Set Up
  2. 选择 Events Manager 方式接入（而非像素代码部署）
  3. 记录 App ID 和 App Secret（后续服务端回传需要）
// 后续服务端回传需要的凭证（妥善保管，不要泄露到前端）
App_ID     = "your_app_id"
App_Secret = "your_app_secret"
Pixel_ID   = "your_pixel_id"
3
配置 Pixel

进入 Events Manager：

  1. Connect Data Sources → Web → 选择 Meta Pixel
  2. 命名 Pixel：WorkHogee_Global_Web
  3. 关联到目标广告账户（Ad Account）
  4. 在 Pixel 设置中开启 Conversions API 开关
提示：Pixel ID 是一个纯数字串（如 1234567890123456），后续回传事件时必须在 URL 中带上。
4
生成 Access Token

在 Events Manager → 选择对应 Pixel → Settings：

  1. 下滑到 Conversions API 区域
  2. 点击 Generate Access Token
  3. 复制生成的 Token（仅显示一次！），存入公司密钥管理系统
// CAPI 回传请求示例（服务端）
POST https://graph.facebook.com/v18.0/{PIXEL_ID}/events?access_token={ACCESS_TOKEN}
Content-Type: application/json

{
  "data": [{
    "event_name": "Lead",
    "event_time": 1726300800,
    "event_id": "lead_20260914_001",  // 用于事件去重
    "action_source": "website",
    "user_data": {
      "em": ["{{sha256(email)}}"],   // SHA-256 哈希后的邮箱
      "ph": ["{{sha256(phone)}}"]
    },
    "custom_data": {
      "currency": "USD",
      "value": 199.0
    }
  }]
}
5
申请 pages_messaging 权限（如需 WhatsApp / Messenger 集成）

如果出海专版需要通过 Messenger 或 WhatsApp 自动回复询盘，需额外申请：

  1. App Dashboard → App Review → Permissions and Features
  2. 找到 pages_messaging，点击 Request Advanced Access
  3. 填写使用场景说明（英文）：说明 WorkHogee 如何代表客户自动回复 Messenger 询盘
6
WhatsApp Business API 申请（如需）

WhatsApp 在欧美客户服务中普及率极高，建议同步申请：

  1. 在 BM 中 Add → WhatsApp Account，创建 WhatsApp Business Account (WABA)
  2. 验证企业手机号：使用公司企业号（非个人号），接收验证码
  3. 在 App Dashboard 添加 WhatsApp 产品
  4. 申请模板消息权限（Message Template）：审核员会逐条审核模板内容
  5. 配置 Webhook 接收入站消息
注意：WhatsApp 模板消息审核严格，营销类模板容易被拒。优先申请"客户服务/通知"类模板（如"您的咨询已收到"），营销内容用自由格式消息（用户发起对话后 24 小时窗口内）。
7
App Review（应用审核）

所有 Advanced Access 权限都必须经过 App Review 才能用于生产环境：

  1. 进入 App Review → Permissions and Features
  2. 逐个点击需要的权限（ads_management、ads_read、pages_read_engagement 等）的 Request Advanced Access
  3. 为每个权限填写：
    • 使用场景说明（英文，详细描述 WorkHogee 如何使用该权限）
    • 录屏演示（英文解说或英文字幕，展示完整操作流程）
    • 隐私政策 URL（指向官网 Privacy Policy 页面）
    • 数据使用说明（Data Use Policy 合规声明）
  4. 提交审核，等待 Meta 团队审核
审核周期：通常 5-10 个工作日。企业认证（Business Verification）若未完成，可能延长至 2-3 周。被拒后可根据反馈修改重新提交，第二次提交通常更快。

Meta 注意事项

  • 测试用户：审核期间可用 Test User（在 App Roles 中添加）测试，无需通过 App Review
  • 隐私政策 URL：必须是公网可访问的完整页面，不能是 PDF 下载链接
  • 数据使用说明：明确说明不向第三方出售数据、遵守 GDPR/CCPA
  • 事件去重：浏览器 Pixel 和服务端 CAPI 同时回传时，必须用相同的 event_id，否则会重复计数

3. Google Ads API 申请流程 P1

前置条件

  • Google Cloud 账号：console.cloud.google.com
  • Google Ads 账号：需具备 管理员（Admin）权限
  • MCC（My Client Center）账号：管理多个广告账户必备，建议用公司主体注册
  • 企业邮箱：使用公司域名邮箱（非 gmail 个人邮箱），否则 OAuth 验证可能被卡
1
创建 Google Cloud Project

进入 Google Cloud Console：

  1. 顶部项目下拉 → New Project
  2. 项目名称：workhogee-global
  3. 选择组织（Organization）为公司主体
  4. 创建后进入该项目
2
启用 Google Ads API

左侧菜单 → APIs & Services → Library：

  1. 搜索 Google Ads API
  2. 点击进入 → Enable
3
配置 OAuth 同意屏幕

左侧菜单 → APIs & Services → OAuth consent screen：

  1. User Type 选择 External（面向海外客户）
  2. 填写 App Information：
    • App name: WorkHogee Global
    • User support email: 公司支持邮箱
    • Application home page: https://www.workhogee.com
    • Privacy policy link: 官网隐私政策页 URL
    • Authorized domains: workhogee.com
  3. Scopes 添加：https://www.googleapis.com/auth/adwords
  4. Test users 添加开发测试用的 Gmail 账号
注意：应用发布前处于 "Testing" 状态，只能 100 个测试用户使用。正式上线需点击 PUBLISH APP，并完成 Google 验证（Verification），否则用户授权时会看到"未经验证"警告页。
4
创建 OAuth 2.0 Client ID

左侧菜单 → Credentials → Create Credentials → OAuth client ID：

  1. Application type: Web application
  2. Name: WorkHogee Global Web Client
  3. Authorized redirect URIs: 添加回调地址，如 https://api.workhogee.com/oauth/google/callback
  4. 创建后下载 JSON 凭证（妥善保存）
// OAuth 2.0 授权码流程（服务端实现）
1. 引导用户访问授权 URL：
   https://accounts.google.com/o/oauth2/v2/auth?
     client_id={CLIENT_ID}&
     redirect_uri={CALLBACK_URL}&
     scope=https://www.googleapis.com/auth/adwords&
     response_type=code&
     access_type=offline          // 必须！否则不返回 refresh_token

2. 回调中拿到 code，换取 access_token + refresh_token
3. 后续用 refresh_token 自动续期 access_token
5
获取 Developer Token

登录 Google Ads（使用 MCC 账号）：

  1. 工具图标 → Setup → API Center
  2. 点击 Request access
  3. 选择 Basic Access（测试阶段足够）
  4. 填写使用说明（英文）：说明 WorkHogee 如何使用 API 管理客户广告账户
  5. 提交后等待审核
6
测试连接

使用测试账号调用 API 验证凭证可用：

// 简单测试：获取客户账户列表
curl -H "Authorization: Bearer {ACCESS_TOKEN}" \
     -H "developer-token: {DEVELOPER_TOKEN}" \
     -H "login-customer-id: {MCC_CUSTOMER_ID}" \
     https://googleads.googleapis.com/v18/customers:listAccessibleCustomers

返回 JSON 中包含可访问的 customerId 列表即表示连通成功。

7
申请标准访问权限（Standard Access）

Basic Access 有严格的配额限制（每天数百次请求），生产环境需升级：

  1. 在 API Center 中，Developer Token 默认是 Test 级别
  2. 点击 Apply for Basic Access（首次）
  3. 使用一段时间后，再申请 Standard Access（配额提升至每分钟数千次）
  4. Standard Access 申请需说明业务规模、调用频率、错误处理机制
审核周期：Developer Token 申请通常 1-3 个工作日；OAuth 验证（Verification）可能需要 1-2 周；Standard Access 升级需 1-4 周。

Google 注意事项

  • OAuth scope：必须使用 https://www.googleapis.com/auth/adwords，不要扩大范围
  • Refresh Token 管理：每个 OAuth Client 的 Refresh Token 数量有限（100 个），需设计复用和回收机制
  • login-customer-id：调用客户账户 API 时必须传 MCC 的 customer ID 作为 header
  • Conversion Adjustments：回传转化时用 conversions:upload，并通过 gclid 或 cart_data 关联广告点击

4. TikTok Business API 申请流程 P2

前置条件

  • TikTok Business Account：企业号，需完成蓝V认证
  • TikTok Ads Account：广告账户（在 Ads Manager 中创建）
  • 企业认证：TikTok 的企业认证流程与 Meta 独立，需单独提交
  • 官网隐私政策：同 Meta，必须公网可访问
1
创建 TikTok Developer App

访问 developers.tiktok.com：

  1. 使用 Business Account 登录
  2. My Apps → Connect an App
  3. 填写 App 名称：WorkHogee Global
  4. 选择 App 类型：Web
2
配置应用信息

填写完整的应用资料：

  • App 名称、描述（英文）
  • Privacy Policy URL：官网隐私政策页
  • Redirect URI：如 https://api.workhogee.com/oauth/tiktok/callback
  • App Icon：1024x1024 PNG
  • Category：选择 Marketing / Advertising
3
申请 Scope（权限范围）

根据业务需要勾选：

Scope用途是否必须
ads.management管理广告计划、报表拉取必须
ads.read读取广告数据（只读）必须
user_info获取授权用户基本信息建议
business_license企业授权相关视情况
4
提交审核（App Review）
  1. 在 App 编辑页点击 Submit for Review
  2. 填写使用场景说明（英文）：WorkHogee 如何帮助海外企业管理 TikTok 广告、回传转化事件
  3. 上传产品演示视频（2-3 分钟，英文解说）
  4. 填写目标用户群体、数据处理方式
  5. 提交后等待 TikTok 审核团队邮件回复
审核周期：通常 3-7 个工作日。TikTok 对中国主体开发者的审核较严格，建议演示视频中明确展示产品面向海外客户。
5
获取 Access Token（OAuth 2.0 授权码流程） 
// TikTok OAuth 流程
1. 引导用户访问授权 URL：
   https://www.tiktok.com/v2/auth/authorize/?
     client_key={CLIENT_KEY}&
     scope=ads.management,ads.read&
     response_type=code&
     redirect_uri={CALLBACK_URL}

2. 回调拿到 code，POST 到：
   https://business-api.tiktok.com/open_api/v1.3/oauth2/access_token/
   body: { client_key, client_secret, auth_code, grant_type: "authorization_code" }

3. 返回 access_token + refresh_token
6
Events API 配置（Server-Side 事件回传）
  1. 进入 TikTok Events Manager
  2. Web Events → Set Up Web Events → 选择 Manage API events
  3. 创建 Pixel，命名 WorkHogee_Global_Web
  4. 获取 Pixel Code 和 Access Token
  5. 配置 Server-Side 事件回传端点
// TikTok Events API 回传示例
POST https://business-api.tiktok.com/open_api/v1.3/event/track/
Headers:
  Access-Token: {ACCESS_TOKEN}
  Content-Type: application/json

Body:
{
  "event_source_type": "web",
  "pixel_code": "{PIXEL_CODE}",
  "data": [{
    "event": "CompletePayment",
    "event_time": 1726300800,
    "event_id": "lead_20260914_001",   // 事件去重 ID
    "user": {
      "email": "{{sha256(email)}}"
    },
    "properties": {
      "currency": "USD",
      "value": 199.0
    }
  }]
}

TikTok 注意事项

  • 区域限制：TikTok Business API 在部分国家/地区不可用，需提前确认目标市场支持
  • 事件去重：浏览器 Pixel 和 Server-Side 同时回传时，使用相同 event_id 去重
  • 数据哈希：邮箱、电话等用户标识必须 SHA-256 哈希后再上传
  • 审核沟通：TikTok 审核通过邮件沟通，务必用公司邮箱接收，不要错过回复

6. 需要准备的材料清单（Checklist）

启动申请前，请确认以下材料已全部准备完毕。缺少任何一项都可能导致审核被拒或周期延长。

  • 企业营业执照（中英文）：扫描件，英文翻译件需翻译公司盖章或自行翻译后公证
  • 企业官网：公网可访问，包含 About / Contact / Privacy Policy / Terms 页面
  • 隐私政策文档（Privacy Policy）：符合 GDPR / CCPA 要求，明确说明数据收集、使用、共享、删除流程
  • 服务条款文档（Terms of Service）：用户使用协议
  • 公司介绍 PPT（英文）：10-15 页，含公司背景、产品截图、客户案例
  • 产品演示录屏：2-3 分钟，英文解说或英文字幕，展示核心功能（特别是数据如何被使用）
  • 数据处理协议（DPA）模板：如平台要求签署 DPA，需提前准备
  • 各平台账号信息汇总表：BM ID / MCC ID / TikTok Business ID / 广告账户 ID / 联系人邮箱
  • 企业邮箱：使用公司域名邮箱（如 ops@workhogee.com），不要用 Gmail / QQ 邮箱
  • 企业电话：可接听国际电话，用于电话验证
  • 域名验证文件：在官网根目录放置平台提供的验证 HTML 文件或 DNS TXT 记录
建议：建立一个共享文档（飞书 / Notion），实时记录每个平台的申请进度、提交时间、审核状态、被拒原因。每周同步一次。

7. 常见问题 FAQ

审核被拒了怎么办？
先仔细阅读拒绝邮件中的具体原因（Meta 通常会指出是哪一步不合格）。常见原因：隐私政策页面不完整、录屏未覆盖所有申请的权限、使用场景描述模糊。修改后重新提交即可，第二次提交通常审核更快。如果连续被拒 3 次以上，考虑通过平台商务渠道（BD）沟通。
测试环境怎么用？
三个平台都提供 Test Mode：Meta 用 Test User（App Roles 添加）；Google Developer Token 申请后默认是 Test 级别；TikTok 在 App 未审核通过前可使用 Sandbox 环境。测试环境下回传的事件不会真实影响广告投放，但可以验证代码逻辑。
多客户账号怎么管理？
每个平台都有"代理/合作伙伴"模式：Meta 用 Business Manager 授权客户的 BM；Google 用 MCC（My Client Center）关联客户广告账户；TikTok 用 Partner 模式让客户授权广告账户。WorkHogee 作为技术服务商，需要走 Partner 认证流程，而非每个客户单独创建 App。
Access Token 过期了怎么办？
Meta 的 System User Token 不过期（推荐使用），User Token 60 天过期；Google 用 Refresh Token 自动续期；TikTok 的 Refresh Token 有效期 365 天。系统层面应统一封装 Token 刷新逻辑，过期前自动调用刷新接口，不要硬编码长期 Token。
企业认证一直不通过怎么办？
常见原因：营业执照与官网域名不匹配、电话无人接听、公司地址与注册地址不一致。确保：(1) 官网底部展示公司全称（与营业执照一致）；(2) 注册公司电话有人接听国际来电；(3) 域名是公司主体注册的（不是个人域名）。如长期不通过，可提交申诉工单。
回传事件失败怎么排查？
按以下顺序排查：(1) Token 是否过期；(2) Pixel ID / Account ID 是否正确；(3) 请求体格式是否符合平台规范（特别是用户数据哈希）；(4) 查看平台 Events Manager 的事件接收情况（Meta/TikTok 有实时事件调试工具）；(5) 检查 event_id 是否与浏览器 Pixel 重复。
需要同时部署浏览器 Pixel 和 Server-Side 回传吗？
是的。最佳实践是双轨部署：浏览器 Pixel 覆盖 iOS/Safari 等受限场景，Server-Side CAPI 补充其余事件。两者必须使用相同的 event_id 去重，否则平台会重复计数。WorkHogee 出海专版默认同时启用两者。
三个平台必须全部申请吗？
不一定。P0 是 Meta（因为大部分出海客户主投 Meta）。Google 和 TikTok 视客户投放渠道决定。如果当前客户 80% 预算在 Meta，可以先只做 Meta，后续再补 Google/TikTok。但企业认证（Business Verification）建议一次性完成，避免后续重复审核。
