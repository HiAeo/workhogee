# 阿果（数据/收银伙计）打通 · 接口契约与验收规格 v1

> 本文件是前后端并行开发的**唯一契约**，冻结路由、请求/响应、KV 键、字段口径、验收红线。
> 数字口径与 schema 不得擅自更改；发现契约漏洞先停下上报，不得各自发挥。
> 全程简体中文、深色主题。所有 LLM/HTTP 调用：单次硬超时 + 整轮总时限 + 受控并发 + AbortController，禁止无界轮询。

## 0. 闭环
外部平台数据回收（截图 VL / 手动）→ 落 KV → 现算聚合 + 第一方数据（analyticsOverview）→ COPY 模型出报告 → 结构化 insights 落库 → 反哺阿图 /generate、阿文 /copy 下次生成。

## 1. 新增后端模块
- 新文件 `server-cloudflare/agu.js`，导出 `handleAgu(request, env, ctx, origin)`：内部 try/catch 兜底（参照 analytics.js 的 handleAnalytics 包装），任何异常返回带 CORS 的 500 JSON，不冒泡成 CF 1101。
- 在 `worker.js` 挂载：在 `handleAnalytics` 之前判断 `path.startsWith('/agu')` 时 `return handleAgu(...)`。复用现有 `json()` 与 CORS 约定（参考 analytics.js 的 `J`/`cors`，agu.js 内自带等价实现即可）。
- 所有路由会员必填：`getMemberSession(env, request)`，`shop = session.id`，未登录 401 `{ok:false,error:{code:'unauthorized'}}`。suspended 账号 403。
- VL 调用复用 `vision.js` 的 `chatVisionCustom(env,{system,user,images,maxTokens,temperature,timeoutMs})`（已关思考、已 JSON 容错）。
- 数据层函数写在 `analytics-store.js`（与现有 ext/insight 同风格：getJson/putJson、零 list、店隔离、indexAdd 风格索引），由 agu.js import。

## 2. 路由清单（前缀 /agu）
| 方法/路径 | 作用 |
|---|---|
| POST /agu/read-shot | 截图 VL 识别，返回结构化指标（不识别为 null，禁编造） |
| POST /agu/metrics | 提交 1 条或数组（≤10）外部指标，落库；同 task+platform+date upsert |
| GET /agu/metrics?task_id=&from=&to= | 列出本店外部指标（可按任务/日期） |
| POST /agu/report | 聚合 + LLM 生成报告并缓存（body.force=true 强制重算） |
| GET /agu/report?task_id= | 取缓存报告（无则 data:null） |
| GET /agu/insights?task_id=&limit=&scope=task\|all | 取 insights（默认 scope=all，limit=20） |
| POST /agu/insights | （可选）手动补一条 insight |
| POST /agu/oauth-interest | 登记某平台 OAuth 等待（真实落库） |
| GET /agu/oauth-status | 返回固定「即将开放」平台清单 + 本店已登记项 |

## 3. POST /agu/read-shot
请求：`{ image: dataURL(必填), task_id?, platform_hint? }`。
VL 用 chatVisionCustom，system 要点：
- 只输出一个 JSON 对象，无 markdown/解释；
- platform 只能取：`xhs, douyin, pyq, gzh, shipinhao, kuaishou, taobao, jd, amazon, tiktok, other`；
- 识别截图中「数据日期 date(YYYY-MM-DD，识别不到 null)、发布天数 days、浏览/播放 views、点赞 likes、收藏 collects、评论 comments、分享 shares、咨询/留资 leads、成交 deals、内容标题 post_title」；
- 数字统一成整数（1.2万→12000，3.5k→3500，"1,200"→1200）；**截图里没有的字段一律 null，严禁估算/编造**；
- 另返回 `fields_present:[...]`：成功读到的字段名数组。
成功响应：
```
{ ok:true, data:{ platform, date, days, views, likes, collects, comments,
  shares, leads, deals, post_title, fields_present } }
```
失败（无 key/超时/解析不出）：`{ ok:false, error:{code:'read_shot_failed'|'vision_timeout'..., message} }`，HTTP 200（业务失败用 ok:false，前端据此降级手动填，不报错卡死）。

## 4. 外部指标存储
KV（binding MEMBERS），零 list、店隔离：
- 实体 `ext:${shop}:${ext_id}`
- 任务索引 `exttask:${shop}:${task_id}` = ext_id 数组（去重追加）
- 全店索引 `extshop:${shop}` = ext_id 数组
- 幂等 `extdedup:${shop}:${task_id}:${platform}:${date}` = ext_id（命中则更新该记录而非新增）
ext 记录：
```
{ ext_id, shop_id, task_id, platform, date,           // date = 数据日期 YYYY-MM-DD
  views, likes, collects, comments, shares, leads, deals,   // 整数或 null
  days:null, image_type:'', copy_version:'', post_title:'', post_url:'',
  source:'screenshot'|'manual', created_at, updated_at }
```
POST /agu/metrics 响应：`{ ok:true, results:[{ext_id, ...记录}] }`；非法（无 platform、无 task_id、全字段空）→ 400。
GET /agu/metrics：`{ ok:true, data:[记录...], meta:{generated_at} }`，按 date/created_at 倒序。

## 5. POST /agu/report
请求 `{ task_id(必填), from?, to?, force? }`。
- 取该任务全部 ext（exttask 索引）；日期范围缺省 = ext 最小/最大 date（无 ext 则 400 `no_data`）。
- **确定性现算（JS，绝不让 LLM 算数）**：
  - engagement = likes+collects+comments（null 按 0，另记字段覆盖率 coverage）；
  - engagement_rate = engagement/views*100；lead_rate = leads/views*100；deal_rate = deals/leads*100（无 leads 为 null）；
  - 分组 by_platform / by_image(image_type) / by_copy(copy_version)：组内先求和再算率（不得对率取平均）；
  - funnel：views → engagement → leads → deals，带 rate_from_prev；
  - trend：按 date 聚合 views/engagement/leads/deals；
  - ranking：lead_rate 优先、次 engagement_rate、次 views，选出 best_platform/best_image/best_copy（样本 views=0 的不参与排名）。
- 第一方：`analyticsOverview(env, shop, from, to)` 复用，结果放 `first_party`（可能为 null）。外部 views 与第一方 PV 是不同触点，**不得混为一个指标**；combined 仅做「总触达」并在 meta 注明口径与来源。
- LLM（COPY_MODEL，关思考，温度 0.3，超时 40s）：输入 = 上述确定性数值摘要（紧凑文本），system 要求输出 JSON：
```
{ headline, summary,
  best:[{what, why}],                 // why 必须引用具体数字
  findings:[...],                     // 客观发现，每条带数字
  actions:[{action, target, expected}], // 具体可执行、非空话（指明改哪张图/哪个标题/哪个平台怎么调）
  insights:[
    {dimension:'image'|'copy'|'platform'|'audience'|'other',
     metric:'engagement_rate'|'lead_rate'|'views'|'other',
     text:'一句话可执行结论', detail:'', magnitude:null, platform:''|'*', positive:true}
  ],
  compliance_note }
```
  合规：不写绝对化（最好/第一/100%/永久）、不写医疗/功效承诺、不编造数字，只能基于给定数值。
- insights 落库（见第 6 节），报告整体缓存 `extrep:${shop}:${task_id}`。
报告对象：
```
{ ok:true, task_id, from, to, generated_at,
  data:{ totals_ext, by_platform, by_image, by_copy, funnel, ranking, trend,
         first_party, combined, coverage },
  narrative:{ headline, summary, best, findings, actions, compliance_note },
  insights:[已落库的 insight 记录],
  meta:{ sources:['external'|'first_party'], tz:'Asia/Shanghai', model, data_completeness, note } }
```
LLM 失败：报告仍返回确定性 `data`，`narrative` 给 `{available:false, reason}`，HTTP 200（不阻断看数）。

## 6. insights 与反哺
KV：实体 `ins:${shop}:${ins_id}`；全店索引 `insindex:${shop}`；任务索引 `instask:${shop}:${task_id}`（均为 id 数组，新项前插）。
insight 记录：
```
{ ins_id, shop_id, task_id, platform:''|'*', dimension, metric,
  text, detail, magnitude:null, positive:true,
  source_report_at, created_at, uses:0 }
```
agu.js 导出供 worker.js 使用：
- `getTopInsights(env, shop, limit=6)`：取本店高信号 insights（去重、按 |magnitude|/新旧，dimension 覆盖 image/copy/platform），返回记录数组；任何异常返回 []，**绝不抛错、绝不阻塞生成**。
- `buildInsightsContext(env, shop)`：返回拼接好的多行文本（空则 ''），内部单次 KV 读取 + 硬超时保护。

注入点（改 worker.js，best-effort，包 try/catch，失败完全不影响原功能）：
- handleGenerate：在 callSeedream 之前，把 `buildInsightsContext` 结果以「【本会员历史投放经验，供参考，优先体现在构图/场景/标题方向】」追加到 `seedPrompt`；响应 JSON 增加 `insights_used:<int>`（实际注入条数，0 即未注入）。
- handleCopy：取 insights 文本追加到 `extra`（或等价上下文位）传入 generateCopy；响应 JSON 增加 `insights_used:<int>`。

## 7. 前端（workbench.html）契约
- 新增平台目录 `AGU_PLATFORMS`（不要动阿发用的 RELAY_PLATFORMS）：id 对齐第 3 节 platform 枚举，含中文名：小红书/抖音/朋友圈/公众号/视频号/快手/淘宝/京东/亚马逊/TikTok/其他。
- 删除「自动读数还在内测」等占位文案（relayAguShot、relayAguManual 两处）。
- 截图上传：FileReader 后显示「正在识别…」→ POST /agu/read-shot → 成功则用返回 data 自动回填表单（platform 映射到 AGU_PLATFORMS，null 字段留空），给「识别结果，请核对」+缩略图；失败则诚实提示「没识别成功，手动填一下」进空表单，不报错卡死。
- 表单字段对齐 ext：平台、数据日期 date（默认今天）、发布天数 days、浏览/播放、点赞、收藏、评论、分享、咨询/留资、成交，以及选填 图种 image_type、文案版本 copy_version；沿用 .agu-form 深色栅格，窄屏单列。
- 提交：POST /agu/metrics 真实落库（同时保留 state.aguData 即时展示），展示现算互动率/咨询率；主按钮「看效果报告」始终可用；当 days≥3 提示「数据已够 3 天，建议看报告」。
- 报告展示：对话内结构化卡片——headline、KPI 行、**轻量内联 SVG 图**（平台对比条形、趋势折线，不引重型库，深色配色，阿果紫 #c084fc 为主）、漏斗、best（what+why）、findings、actions（具体）、来源标注（外部平台 / 自有 H5）；按钮「重新生成」(force)、「在效果中心查看」。
- 效果中心（openAnalytics/AG）：顶部加分段切换「自有触点 / 外部平台 / 综合总览」，默认自有触点；外部视图 GET /agu/metrics（全店、按 range）按平台行展示浏览/互动率/咨询率/成交并标来源标签；综合总览合并但必须逐条标来源。原第一方逻辑不动。
- OAuth：rf_agu_api 改为打开「即将开放」真实卡片：列平台 +「可登记」→ POST /agu/oauth-interest，已登记显示状态；**禁止假的「立即连接/已授权」按钮**。
- 版本号：APP_VER 由 v0.9.5 Alpha 升到 v0.9.6 Alpha，并在「版本更新」日志追加阿果本次能力条目。

## 8. 真机 E2E 验收（Playwright，禁止虚报）
本地：`npx wrangler dev`（后端，吃 .dev.vars，本地 KV）+ 静态伺服 workbench.html；用 Playwright `page.route` 把 `https://api.workhogee.com/**` 改写指向本地后端。
测试截图夹具：用 Playwright 把一个含**已知数字**的仿小红书/抖音后台数据 HTML 页面截图，作为上传图；断言自动回填值 = 已知值。
完整漏斗：注册/登录 → 上传商品图 → 阿图 → 阿文 → 阿视 → 阿发（建 H5 画册；另开浏览器上下文打开 H5/点击/留资制造第一方数据）→ 阿果：
1) 截图识别自动回填正确；2) 提交后**刷新页面、退出重登**数据仍在（GET /agu/metrics 可查）；3) 报告真实生成，narrative 的数字与 data 现算一致、actions 具体、无绝对化/医疗词；4) insights 落库（GET /agu/insights 可查）；5) 再开一单，阿图 /generate、阿文 /copy 响应 `insights_used>0`。
全程无 console error、无卡死/无界等待。造少量数据，预计 <¥5，硬上限 ¥15；失败/拒收 0 计费，任何超支风险停下上报。
